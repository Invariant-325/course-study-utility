# 学习通课程自动连播助手（自然播放版）

按平台正常规则连续播放课程视频：**默认 1.0 倍速、不改进度、不伪造时长、不绕过检测**。
播完自动进下一个视频任务点，本章播完自动进下一节，全程有面板和日志。

> 当前版本 `0.1.0`。
> **状态说明**：阶段 B 技术设计已按审阅意见修订（见 [阶段B-技术设计-v2-修订版.md](docs/阶段B-技术设计-v2-修订版.md)）。
> 阶段 C 的现有代码**尚未按修订设计改造**——按第 5 点要求，先用只读探针在真实页面取证，再决定改造幅度与是否改为 fork MIT 项目。
> 在使用任何自动化能力之前，请先执行本文第 0 节。

---

## 0. 使用前必做：先跑只读探针

`probe/chaoxing-probe.user.js` 是**只读**诊断脚本：不点击、不播放、不修改页面 DOM，只用 `postMessage` 把各层 iframe 的自采数据汇总到顶层。

1. 装进 Tampermonkey（和主脚本并存不冲突，`@grant none`）。
2. 打开学习通课程学习页，等 6 秒。
3. 点右下角 **「📋 导出探针数据」**，JSON 会复制到剪贴板。
4. 把 JSON 发我。

它回答的正是修订设计里悬而未决的问题：

| 你的疑问 | 看 JSON 里的哪个字段 |
|---|---|
| 视频播放器是否跨域 | `frames[].sameOriginDoc` / `summary.crossOriginCount` |
| 嵌套有多深 | `frames[].depth`（已按真实嵌套计算） |
| 完成态用哪个信号 | `summary.jobStates`（class / label / 无标记各多少） |
| 任务点容器是不是 `.ans-job` | `summary.totalJobs` 与 `topReport.jobs[]` |
| 目录是 `#coursetree` 还是 `.posCatalog_level` | `topReport.catalog.root` / `catalogEntries` |
| 有没有弹题容器 | `summary.hasVideoQuiz` |
| 播放器在不在 iframe 里 | `frames[].src` 含 `/ananas/modules/video/` |
| 切章按钮是哪个 | `summary.hasPrevNextFocusNext` / `hasNextChapter` |

探针输出经本地冒烟测试验证结构合法（`node tests/probe-smoke.mjs`）。**跨域字段无法在 jsdom 中模拟，只能靠你的真实页面确认。**

## 2. 安装

### 方式一：直接用构建产物（推荐）

1. 浏览器安装 **Tampermonkey**（Edge/Chrome 扩展商店搜索“篡改猴”）。
2. **必须开启「允许用户脚本」**：
   - `edge://extensions` 或 `chrome://extensions` → 找到 Tampermonkey → 详细信息 → 打开「允许用户脚本」。
3. 打开 Tampermonkey 面板 → 「添加新脚本」→ 清空编辑器 → 粘贴 `dist/chaoxing-helper.user.js` 全文 → `Ctrl+S` 保存。
4. 打开学习通课程学习页（地址形如 `.../mycourse/studentstudy?...`），刷新页面。

### 方式二：从源码构建

```bash
cd chaoxing-helper
node build.mjs      # 生成 dist/chaoxing-helper.user.js
node --check dist/chaoxing-helper.user.js   # 语法自检
```

改任何逻辑请改 `src/` 下的文件，不要改 `dist/`（会被覆盖）。

## 3. 使用

进入课程学习页后，右上角出现面板：

| 元素 | 说明 |
|---|---|
| 状态徽章 | 未启动 / 定位任务点 / 播放中 / 等待平台记录完成 / 切换下一个 / 已暂停 / 需要人工处理 / 本课程已完成 |
| 开始 | 找到第一个**平台标记为未完成**的视频任务点并播放 |
| 暂停 / 继续 | 暂停会立刻停手并留下状态；继续会接着当前任务点往下走 |
| 停止 | 结束本次运行 |
| 课程/节点 | 当前任务点标题 |
| 播放状态 | 播放/暂停 + 当前倍速 + 进度时间 |
| 章节进度 | 第 x / y 节（读页面目录，读不到会明确显示“未识别目录”） |
| 已播视频 | 本次运行播放过的视频数 |
| 自动切换 | 自动切换中 / 已暂停 / 需人工 / 课程完成 |
| AI 请求 | 阶段 C 固定为 0 次（阶段 D 接入后才有值） |
| 最近错误 | 只有出错时出现 |
| 调试日志 | 勾选后弹出日志区，同时把日志级别降到 debug |
| 诊断导出 | **重要**：把当前页面结构导出成 JSON 并复制到剪贴板 |
| 复位面板 | 位置跑偏时把面板放回右上角 |

面板可拖动（按住标题栏），可折叠（`—` 按钮），位置会记住。默认停在右上角，不压播放器中央控制区。

## 4. 它具体怎么做（与需求逐条对应）

| 你的要求 | 实现 |
|---|---|
| 1. 识别播放器 | `CourseTree.findVideoInJob()`：任务点容器直查 → 逐层 iframe 深度查找（最多 2 层），候选 `#video_html5_api` / `video.vjs-tech` / `video` |
| 2. 正常播放、默认 1.0 倍速 | `VideoCtl.play()` 每次播放前把 `playbackRate` 纠正为 `1`；`Config.set('playbackRate', 任意值)` 在代码层被拒绝；不 seek、不静音 |
| 3. 自然结束检测 | 监听 `ended` 事件为主，`timeupdate` 兜底（`currentTime >= duration - 0.5`），同一视频只触发一次 |
| 4. 同章多视频 | `pickNextVideoTarget(jobs, currentId)` 在任务点序列里从当前位置向后找下一个**未完成**项 |
| 5. 章节自动推进 | 同页无未完成 → 先点目录中当前项的下一项 → 再退化到页面「下一节」按钮 → 等页面结构变化后重新定位 |
| 6. 已完成不重播 | 完成态只信平台渲染的 `.ans-job-icon[aria-label]` 与 `.ans-job-finished`；本地断点仅用于提示 |
| 7. 全部完成停止 | 没有未完成任务点且没有下一节时进入「本课程已完成」 |
| 8. 暂停/继续/停止/断点 | 面板按钮 + 油猴菜单命令；断点写 `cursor`（仅提示用） |
| 9. 弹题 | **阶段 D**，本版本未实现；当前行为是：意外暂停超过 3 次 → 判定「需要人工处理」并停止，不会无限重试 |

## 5. 异常恢复策略（全部有限次）

| 场景 | 行为 | 上限 |
|---|---|---|
| 拿不到 video | 等 iframe 就绪后重试定位 | 6 次 × 2.5s |
| `play()` 被拒 | 记录并提示“请在页面点一下”，不静音绕过 | 3 次 |
| 意外暂停（非 ended） | 自动恢复播放 | 3 次，超过则转「需要人工处理」 |
| 你手动点了播放器/页面 | **视为人工接管，不抢回播放**，直接进入暂停态 | — |
| 视频结束但平台未记为完成 | 观察完成态变化 | 20s |
| 超时且播放头已到末尾 | 记 warning 后进入下一个，**不重播本视频** | — |
| 超时且播放头未到末尾 | 转「需要人工处理」 | — |
| 切章点击无效果 | 重新定位 | 单次运行累计 200 次 |
| 视频 `error` 事件 | 立即停止并报告，**不自动刷新整页** | — |

> 设计上刻意**永不自动刷新整页**：刷新会丢播放状态，也容易被判为异常行为。

## 6. 诊断导出（后续适配的关键）

现有选择器来自对开源项目的审计与交叉验证，**没有在你的真实页面验证过**。第一次使用如果面板显示「未发现任何任务点」或「存在无法判定完成状态的任务点」：

1. 点面板的 **诊断导出**，JSON 会复制到剪贴板（同时也打印在控制台）。
2. 把那一段发我，重点看这几段：
   - `documents[]`：iframe 层级、每层的 `.ans-job` / `.ans-job-icon` 数量
   - `jobs[]`：每个任务点的 `state` / `stateBy` / `type` / `hasVideo` / `frameUrl`
   - `catalog`：目录根选择器命中情况与条目数
   - `nextButtons`：`#prevNextFocusNext` / `.nextChapter` 是否存在
3. 我按真实结构收敛 `src/30-selectors.js`（所有选择器都集中在这一个文件里）。

`jobs[].stateBy` 会是 `class` / `label` / `label-unknown` / `none` 之一 —— 它直接告诉你哪个判定信号生效了。

## 7. 安全与合规（代码层已固定，不可配置）

- `@grant` 只申请 `GM_getValue` / `GM_setValue` / `GM_registerMenuCommand`。
- `@noframes`，只在顶层运行；跨域 iframe 直接跳过，不做任何绕过尝试。
- 零 `@require`、零 CDN、零 `eval` / `new Function`、零远程代码。
- 不拦截 `blur` / `visibilitychange` / `mouseleave` / `mouseout`；不读写 `document.hidden` / `visibilityState`。
- 不修改 `currentTime`，不调用 `seek`，不伪造学习时长或心跳。
- 不读 Cookie、不碰账号凭证、不调用任何 chaoxing 写接口。
- 切到后台时，视频按平台自己的规则暂停；脚本**只提示、不自动恢复**（这是你选定的 B 策略）。

| 5 | 观察是否切换 | 自动跳到同章下一个未完成视频；日志出现「同页下一个任务点」 |

| 7 | 手动点暂停 | 状态变「已暂停」，且**脚本不会自己恢复播放** |

| 10 | 已完成的章节 | 不会被再次播放（日志会跳过它） |

如果第 2 步 `jobs.length === 0`：说明任务点容器选择器不匹配你的页面版本 → 把诊断 JSON 发我。
如果第 3 步状态直接变「需要人工处理」：把面板里「最近错误」和诊断 JSON 发我。

## 9. 已知限制（诚实说明）

1. **选择器未在你的真实页面验证**。已做多候选与多信号回退，但仍可能需要按诊断结果微调。
2. 完成态判定依赖平台渲染的 `aria-label` 文案。不同学校/版本若用别的文案，需要改 `SEL.iconLabelUnfinished` / `iconLabelFinished` 两个数组。
3. 目录结构有两代（`#coursetree` 与 `.posCatalog_level`），已都做了候选；若你的页面是第三种，需要补。
4. 「视频结束但平台未记为完成」时脚本选择**继续下一个而不是重播**。这是为了避免无限重播；代价是个别情况下该任务点可能需要你手动补几秒。
5. 弹题（阶段 D）尚未实现。当前遇到弹题会因“反复暂停”而停止并要求人工处理——这符合“不允许无限循环”的要求，但不是最终形态。
