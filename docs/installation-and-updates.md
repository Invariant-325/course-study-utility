# 安装与版本更新（核对版）

## 手动更新

当前没有自动更新检查、自动下载或自动安装。0.1.3 的“更新说明”按钮仅显示文字，不会调用更新服务。应用仍会访问学习通及用户配置的模型服务，“不检查更新”不代表整个程序不联网。

建议退出旧版，再运行新安装包。0.1.2、0.1.3 使用 oneClick=true、perMachine=false，安装结束后会启动程序。v0.1.1 是带安装向导的版本。旧版曾允许选择安装目录，因此具体安装位置应查看桌面快捷方式或应用报告的路径，不保证所有版本都安装到同一固定目录。

各版本 appId 都是 com.local.chaoxing.helper，0.1.1 起 EXE 名为 ChaoxingHelper.exe，这有助于识别同一应用；并不意味着任意历史版本、不同安装目录及配置迁移组合都已验证兼容。0.1.3 覆盖安装与登录保持需要单独实测。

## 登录和设置

默认数据目录为 `%APPDATA%/chaoxing-helper-desktop`，其中包括持久会话、store.json、dsh-home 与日志。覆盖安装通常保留独立的数据目录，但登录是否继续有效，还取决于平台 Cookie、账号状态和会话策略，不能保证永远不用重新登录。

当前 NSIS 配置 deleteAppDataOnUninstall=false。卸载默认保留数据，不应承诺一定出现“是否删除登录数据”的询问。

## 0.1.3 增加的入口

- 主进程提供 app:info IPC，返回版本和安装相关信息。
- 预加载桥暴露 appInfo()。
- 控制面板底部显示版本号，并提供手动更新说明。

本次归档已核对安装包相邻 app.asar 与对应运行源码一致，并检查 JavaScript 语法；没有重新完成 0.1.3 的安装、覆盖升级、账号登录或测验端到端验收。

## 章节测验行为

0.1.2 起源码增加默认启用的 quizGateEnabled：本节视频结束后，若检测到未完成测验，会尝试识别、填写并提交，再继续推进。submitAndConfirm() 还会尝试处理平台二次确认弹窗。它与旧版“只填写、用户最后提交”的流程不同。

原记录明确指出，实际页面的测验入口点击与二次确认弹窗仍有未验证分支。运行前应了解当前配置和提交行为；需要人工核对时先暂停。详见 [原工程章节测验闸门说明](development/0.1.2-章节测验闸门.md)。
