# 0.1.8 构建记录：EXE 产品资源写入步骤

2026-11-11。针对 Codex《打包与安全警告对比-0.1.7-0.1.8》中发现的封装差异做修正。

## 发现的问题

对比结果：

| 项 | Codex 0.1.7 | 我构建的 0.1.8（修正前） |
|---|---|---|
| 主程序 EXE 产品名 | 课程伴学工具 | **Electron** |
| 主程序 EXE 版本 | 0.1.7 | **33.4.11** |

虽然安装包 SHA256 不同是正常的（构建时间戳等），但**主程序 EXE 的资源元数据没写进去**是实打实的缺陷：用户在任务管理器、文件属性、SmartScreen 提示里看到的都是 "Electron 33.4.11"。

## 原因

`build/after-pack.cjs` 的逻辑：

```js
if (process.env.CHAOXING_RCEDIT) {
  execFileSync(process.env.CHAOXING_RCEDIT, [
    exe, '--set-icon', 'build/icon.ico',
    '--set-file-version', version, '--set-product-version', version,
    '--set-version-string', 'ProductName', '课程伴学工具',
    ...
  ]);
}
```

- 只有环境变量 `CHAOXING_RCEDIT` 存在时才执行
- `package.json` 里 `signAndEditExecutable: false`，所以 electron-builder **不会**自动补资源
- 我之前的构建没有设这个变量 → 这一整段被静默跳过

Codex 的建议正是：不要把它做成某个终端里临时设的变量，要变成明确、可重复、有校验的构建步骤。

## 修改（build 工具链，不改业务逻辑）

`desktop/Build.ps1`：

1. **自动定位 rcedit**，顺序为：`$env:CHAOXING_RCEDIT` → `node_modules/rcedit/bin/rcedit-x64.exe` → Codex 工作区的 `rcedit-x64.exe`
2. 找到就导出为 `CHAOXING_RCEDIT`，让 `after-pack.cjs` 生效
3. 找不到只警告（不阻断构建），并明确提示"EXE 将保留 Electron 默认产品名/版本"
4. **构建后校验**：读回 EXE 的 `VersionInfo`，断言
   - `ProductName` 非空
   - `ProductVersion` 等于 `package.json` 的 version
   - 不一致直接 `throw`，让构建失败
5. 版本号改用 `node -p "require('./package.json').version"` 读取

### 顺带修掉的两个坑

- **Build.ps1 必须是 UTF-8 带 BOM**。文件里含中文（`课程伴学工具`），PowerShell 5.1 会按 ANSI 读，导致单引号配对被破坏、整脚本解析失败（`The string is missing the terminator`）。
- **PowerShell 5.1 的 `ConvertFrom-Json` 对这个 package.json 抛 `ArgumentException`**（对象层级太深），所以不再用它读配置，改由 node 读版本号。
