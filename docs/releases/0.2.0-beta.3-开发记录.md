## 一、学习统计（需求 5）

**位置**：侧栏「学习统计（今日）」卡片。

| 指标 | 来源 | 性质 |
|---|---|---|
| 播放时长 | 客户端按 `playing/settling/awaitingConfirm` 状态累计，10 秒上报一次 | **本机观察值** |
| 识别次数 | 每次 `vision:ask` 计 1 次，含失败数 | 本机观察值 |
| Token | 从 API 返回的 `usage.prompt_tokens/completion_tokens` 累加 | 真实账单口径 |
| 平台确认 | Runner snapshot 的 `confirmedCount` 增量 | **平台返回**，不推断 |

卡片底部写明：*播放与识别是本机观察值；「平台确认」只统计平台返回的完成数，不推断*。

**存储**：`%APPDATA%\chaoxing-helper-desktop\stats.json`，按 `YYYY-MM-DD` 分桶，保留最近 30 天。

```js
{ days: { "2026-11-11": {
  visionCalls, visionOk, visionFail,
  promptTokens, completionTokens,
  playSeconds, tasksConfirmed
} } }
```

**采集点**：`askVision` 返回里新增 `usage` 字段；`vision:ask` 处理器在每次调用后 `bumpStats`，成功失败都计数。

## 二、异常与提醒（需求 4）

**位置**：侧栏「异常与提醒」卡片。

**分类规则**（`ISSUE_RULES`）：

| key | 触发条件 | 提示 |
|---|---|---|
| `login` | blocked/needsReview 且错误含 登录/login/401/auth | 登录状态可能失效 → 重新登录后点「继续」 |
| `stuck` | blocked 且错误含 停滞/stall | 视频播放卡住 → 暂停再继续，多次失败就刷新 |
| `manual` | awaitingConfirm | 等待人工确认 → 继续/停止 |
| `quizfail` | awaitingConfirm 且原因是测验 | 题目无法自动完成 → 核对后手动提交 |
| `nokey` | 未配置 API Key | 去模型设置填 Key |

无异常时显示绿色「当前没有需要处理的异常」。

**通知**：勾选「需要人工处理时暂停任务并弹系统通知」后，每条异常首次出现会调 `app:notify` 弹 Windows 系统通知（同一异常不重复轰炸，取消勾选后重置）。开关状态存 `notifyOnManual`。

> 注：名字里有"暂停任务"，但当前实现只做**通知**，不自动暂停 Runner。自动暂停需要 Runner 暴露暂停入口并在主进程侧拦截，留到后续。

## 三、系统托盘（需求 6）

**行为**：

- 启动时创建托盘图标（`build/icon.ico`，已加入打包 files）
- **关闭窗口 = 收进托盘**，刷课继续跑（`win.hide()`）
- 托盘菜单：状态行（只读）/ 显示主窗口 / 暂停刷课 / 继续刷课 / 结束任务 / 退出程序
- 状态行每 3 秒从页面读一次 `snapshot()`，显示「状态 · 章节 · 进度%」
- 双击托盘图标 = 显示主窗口
- 「退出程序」才真正退出（`isQuitting = true`）

**改动点**：`win.on('close')` 从"直接关闭"改为"隐藏到托盘"，真正退出走托盘菜单；`window-all-closed` 在非退出时不 `app.quit()`。

## 未验证（务必看）

1. **托盘是否真的出现**：`new Tray()` 在目标机器上的行为没跑过。若图标为 `nativeImage.createEmpty()`，Windows 可能显示空白占位
2. **关闭到托盘后刷课是否继续**：逻辑上窗口隐藏不影响 `WebContentsView`，但没实机确认
3. **系统通知是否弹出**：`Notification.isSupported()` 依赖系统通知设置，未实测
4. **播放时长统计准确性**：按轮询间隔（1.2s）估算，10 秒上报一次，存在 ±几秒误差；切到后台时轮询仍在跑（`backgroundThrottling: false`），但窗口隐藏后的定时器行为未验证
5. **Token 统计**：每次调用都用新会话，没有缓存命中，所以账单口径就是全量；但**模型侧如果做了 prompt caching，实际计费可能更低**，这里记的是 `usage` 原值
6. **异常规则是启发式的**：靠 `lastError`/`awaitingReason` 里匹配中文关键词，平台文案一变就会失效
7. **托盘与窗口的关闭竞争**：`close` 事件里同时有"隐藏"和"退出"两条路径，`isQuitting` 的提升声明在文件末尾，运行时安全但静态阅读容易误判

## 下一步建议

1. 装 beta.3，确认托盘图标出现、关闭窗口后进程还在、刷课继续
2. 进课程看「学习统计」播放时长是否跳动、「平台确认」是否与实际完成数一致

4. 确认待办队列的 tasks.json 重启后还在
