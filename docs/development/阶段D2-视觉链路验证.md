## 一、为什么不用 SDK

`@deepseek-ai/dsh-sdk-client` 存在（npm `0.0.1-rc.1`），但它的传输是 **stdio JSON-RPC**。

实测本会话沙箱的限制：

| 方式 | 结果 |
|---|---|
| `spawn(..., { stdio: 'pipe' })` | ❌ `EPERM`（无法创建管道） |
| `stdio: 'ignore'` / `'inherit'` | ✅ |
| `stdio: ['ignore', fd, fd]`（文件描述符） | ✅ |

所以 SDK 的管道模式在本环境不可用，改用 **`dsh headless`（回答一个任务并退出） + 文件描述符重定向**。

## 二、实际版本与配置（全部来自实测，非记忆）

| 项 | 值 | 来源 |
|---|---|---|
| DSH 运行时 | Node 24.21.0 / pnpm 11.28.5 | `runtime/versions.json` |

**隔离方式**：`DSH_HOME` 指向工作区内的 `.dsh-home`，与桌面版 profile 完全分离，不污染、不共享会话。

**模型固定**（写入 `profiles/headless/cordis.patch.yml`）：

```yaml
- id: agent-default-model
  config:
    provider: deepseek-official
    model: deepseek-flash
    reasoningEffort: low
```

`--dump-config` 已确认生效。

**识别质量**（来自会话的 reasoning 输出）：

- 正确读出题干「全面从严治党是新时代党的自我革命的伟大实践…」
- 正确读出 4 个选项全文，字母对应无误
- 结论：选 A（「核心是加强党的领导，基础在全面，关键在严，要害在治」，标准表述）

**关键点**：
- 视觉识别**没有出现**我人工看截图时的「治党→治觉」误读
- 全程 **5.4 秒**
- 最终 stdout 只有一行 JSON，reasoning 走 stderr，不污染结果

## 四、安全边界

| 项 | 做法 |
|---|---|
| API Key | 优先环境变量；缺失时从 `~/.dsh/.credentials.yaml` 的 `refs.DEEPSEEK_API_KEY` 读取，**只在进程内传递，不打印不回显** |
| 权限 | `--permission-mode read-only --approval-policy never` —— 会话不能写文件、无人值守 |
| 提示词 | 明确「不调用执行工具、不操作网页、不修改文件、只输出 JSON」 |
| 输出校验 | `extractJson` 只做 `JSON.parse`，绝不 eval；`validateResult` 校验 questionId 回显、type、status、选项字母合法性 |
| 隔离 | 独立 DSH_HOME；与 Coding Agent 上下文无关 |
| 成本 | 每题一次调用；只传图片 + 题目 ID，不累积上下文 |

## 六、下一步

1. **写 HTTP 桥接服务**（`127.0.0.1:8788`）：`POST /vision` 收 base64 图 + questionId → 落盘 → 调 bridge → 返回 JSON；复用 D1 的 token/Origin 白名单。
2. **浏览器端 Canvas 渲染题目**：克隆题干 + 选项节点，用 `font-cxsecret` 渲染到 Canvas（宽度自适应，高度按内容），导出 PNG。
3. **接入章节测验面板**：分析 → 每题渲染 → 调桥接 → 校验 → 展示建议 → 用户确认后按 `data` 字母填写 → 用户确认提交。
4. 长题干分段：按题目容器高度判断，超出则分 2~3 段渲染。
