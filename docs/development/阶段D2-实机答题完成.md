## 二、答案是怎么来的

全程没有解密字体，也没有人工读题：

1. `ChapterQuizAdapter.parse()` 从 DOM 取题号、题型、题干、选项、显示字母
2. `QuizImage.render()` 用页面已加载的 `font-cxsecret` 在 Canvas 上重绘题目（`1800×644` PNG）
3. 图片经 `fetch` 送到本地桥接 `127.0.0.1:8788`
4. 桥接调 `dsh --profile headless`（`deepseek-flash` + `reasoningEffort: low`，`--permission-mode read-only`）
5. 会话返回严格 JSON，服务端与客户端双重校验后回填

识别结果原文：

```
q_1|single|A    q_2|single|B    q_3|single|A
q_4|multiple|A,C,D    q_5|multiple|A,B,C
```

**多选题的准确度值得一提**：模型正确排除了 q_4 的「B 集体主义」（不是需要纠正的作风问题）和 q_5 的「D 完善制度之笼」（不在「以学铸魂/增智/正风/促干」的排比里）。

## 三、本轮修掉的三个真实 BUG

### 3.1 `data` 与显示字母混淆（最严重）

真实结构 `<span class="num_option" data="D">A</span>` 里，`data` 是平台内部标识，文本才是用户看到的字母。此前把 `data` 当显示字母，渲染出的题目字母顺序与页面不符，会导致答案整体错位。

修复：`option.letter` = 显示字母，`option.internal` = 内部标识，填写按显示字母匹配。

### 3.2 `isSelected` 把 `before-after-checkbox` 误判为已选中

原正则 `/selected|select|cur|active|check/i` 命中了类名里的 "check"，导致所有多选题被判定为"已有答案"，填写被拒绝。

修复：改为连字符/空白边界匹配 `(^|[\s-])(selected|select|active|cur|checked)([\s-]|$)`。

### 3.3 加密题一律禁止填写

原保护是文本识别阶段的产物（读不到题就不能答）。有了视觉答案后这条过于严格，导致 `fill` 直接拒绝。

修复：`fill(question, letters, { source: 'vision' })` 时放行；默认仍禁止，防止在"没有可信答案"的情况下乱填。

## 四、填写与提交的安全链路

| 环节 | 实际表现 |
|---|---|
| 逐题填写 | `fill:1`（点 1 次）/ `fill:3`（多选点 3 次） |
| 填写后自检 | 5 题全部 `verify:ok`（重新读 DOM 比对选中状态） |
| 页面核对 | 人工截图确认：q_4 的 B 未选、q_5 的 D 未选 |
| 提交 | 平台弹出「确认提交？」，点击后才提交 |
| 提交后 | 平台返回成绩，非"点击成功即完成" |
