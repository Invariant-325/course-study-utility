## 二、已修复的关键问题

### P0-1 入口识别
- 抽出 `CourseUrl`，main 与 runner 共用同一判定，**不再各写一份正则**。
- `mooc2-ans/mycourse/*` 明确排除；`studentstudy` 保留；`knowledge/cards` 保留（注释说明它是内层帧，保留为容错）。
- `@match` 收窄，课程主页不再注入。

### P0-2 暂停分诊（此前只有设计，代码里没有）
- 新增 `PauseClassifier`，六类分诊，命中即返回。
- 后台/用户暂停 **一律不自动恢复**，只提示。
- 暂停后 900ms 观察窗口再分类，避免弹题 DOM 未出现时误恢复。
- 只读 `visibilityState`/`hasFocus`/`readyState`/`networkState`，不拦截事件、不写可见性。

### P0-3 完成确认与视频结束分离（此前是错的）
- `settling` 超时**不再**看播放进度就 `goAdvance()`，改为进入 `awaitingConfirm`。
- 面板展示任务名、已等待秒数、已尝试次数，提供三个操作。
- 「跳过并记录」写入 `pendingConfirm`，key 为 `courseId/chapterId/type#index`（`267253952/1248884878/video/#0`），**不含标题**，并跨刷新持久化。
- 被跳过的任务在后续 `pickNextVideoTarget` 中被排除；跳过不计入成功。
- 状态机 `completed` 入口收紧：只能由 `verdict === 'complete'` 触发。

### P0-4 课程完成状态
- 三态：`complete` / `incomplete` / `unverifiable`。
- 视频完成 ≠ 整门课程完成：`completed` 语义改为「视频任务已完成」，若 `pendingOthers > 0` 在面板明示「仍有 N 个非视频任务未处理」。
- 目录统计区分 `firstLayer`（章）与叶子节点，未知计数单独记 `unknown`，不混入 `pending`。

### P0-5 播放停滞
- watchdog 增加停滞判定，默认 75s（可配），区分 loading（`readyState<3` 或 `networkState===2`）与真停滞。
- 真停滞进入 `blocked` 并给出秒数，不无限 `play()`、不刷新页面。

### 选择器落实
- 容器 `.ans-attach-ct` 优先，`.ans-job` 兼容；**嵌套容器只保留最内层**，避免一个任务点统计两次。
- 完成态找不到时向上最多 3 层查找，但祖先若含多个 `.ans-job-icon` 则停止，避免串台。
- `diagnose()` 明确区分：`ok` / `not-loaded` / `frame-inaccessible` / `selector-miss`。

## 七、关于 `CxRobotSdkJs` 的结论更正

上一轮报告把 Console 里的 `[CxRobotSdkJs]` 提示认定为「平台的反自动化检测」，**这个结论不成立，予以更正**。

实际完整文本是：

```
[CxRobotSdkJs] 尊敬的开发者您好，您当前正在使用公共授权认证，
可能存在流控风险和功能限制；建议您及时申请专用授权，认证指南：
https://robot-docs.chaoxing.com/docs/auth
```

同类还有 `[VoiceToonBot]` 的同样提示。这两条都是**第三方 SDK 的授权/流控提示**（面向接入方开发者），说的是「公共授权可能有限流」，**没有证据表明它在检测用户端自动化**。

现有证据不足以下任何关于反自动化的结论。如需判断平台是否检测脚本，需要另行设计对照实验（例如观察平台侧上报字段），不能靠一条 SDK 提示推断。
