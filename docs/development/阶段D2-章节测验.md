### 3.2 结构摘要

### 3.3 实测到的两个关键陷阱

**陷阱 1：选项字母顺序被打乱**

| 题 | 题型 | DOM 顺序对应的字母 |
|---|---|---|
| #1 | 单选 | **D, A, C, B** |
| #2 | 单选 | **A, C, B, D** |
| #3 | 单选 | **A, B, D, C** |
| #4 | 多选 | **C, D, A, B** |
| #5 | 多选 | **C, D, A, B** |

→ 必须读 `span[data]`，按 DOM 索引推断 A/B/C/D 会把答案填错题。适配器已按此实现并有专门回归测试。

**陷阱 2：字体加密（硬阻塞）**

- 题干与选项带 `.font-cxsecret`
- `textContent` 是替换字符：`全面从严治党` 读作 `全嵅从嵆治嵃`
- 字体是 **base64 内联 TTF**（`data:application/font-ttf;base64,…`），渲染后才显示正确文字
- 部分汉字未加密（全/从/治/是/新/时 原样），部分被替换

**渲染验证**：临时插入一个使用 `font-cxsecret` 的元素，页面渲染出的是
「全面从严治党是新时代党的自我革命的伟大实践」—— 说明**字体映射有效，加密只影响读文本，不影响显示**。

**解密可行性验证（失败）**：
用 16×16 Canvas 像素特征做字形比对，结果：

| 加密字 | 真值 | 排名（候选 380 字） |
|---|---|---|
| 嵅 | 面 | **194** |
| 嵆 | 严 | **未命中** |
| 嵃 | 党 | 169 |
| 嵁 | 代 | 13 |

top5 全是「内/情/中/由/被」这类高频字 → **粗粒度像素比对不可行**。精确解密需要解析字体 glyph 轮廓做形状描述子，是独立工程。

**阻断原因（两个，都不可绕过）：**
1. **题目文本加密**：送给模型的将是「全嵅从嵆治嵃」，模型无法理解，请求即使成功也没有意义。

## 七、下一步最少要做的工作

**按优先级：**

1. **决定字体加密怎么办**（阻塞一切）。可选路径：
   - A. 实现精确字形解密：解析内联 TTF 的 glyph 轮廓，用轮廓特征与常用汉字库比对。工作量大（预计 300–500 行），精度需实测；这是 zhu-hailin 用 Typr.js + 355KB 映射表走的路。
   - B. **改用多模态**：把每道题渲染为图片交给支持视觉的模型。规避解密，但依赖用户配置视觉模型，且成本更高。
   - C. 接受限制：加密课程只做结构识别 + 人工录入，不自动答题。
2. 找一门**未加密**的测验课程，跑通 B/C/D（这是验证 AI 链路最快的路径）。
3. 用一次真实填写验证 `isSelected` 假设（填一题 → 读回 → 撤销）。
4. 补判断题与填空题的适配（需要样本）。

## 八、建议

如果目标是「尽快可用」，**路径 2 性价比最高**：先找未加密的测验课程把 AI 链路跑通，加密课程作为独立课题处理。

如果目标课程**全部加密**，那么必须做 A 或 B，且建议先做一个小规模精度实验（比如 50 个字符的正确率）再决定投入。
