## 二、发现并修复的关键 BUG

真实 DOM 结构是：

```html
<span class="num_option" data="D">A</span>
```

- `data="D"` —— 平台**内部答案标识**（被打乱，用于防抓取）
- 文本 `A` —— 用户**实际看到的字母**

我最初把 `data` 当成显示字母，导致渲染出来的题是：

```
D 核心是加强党的领导...
A 核心是正风肃纪反腐...
```

而页面实际显示：

```
A 核心是加强党的领导...
B 核心是正风肃纪反腐...
```

**这会让「用户看到的字母」和「回填时匹配的字母」错位。**

修复后：
- `option.letter` = 显示字母（A/B/C/D，来自 span 文本）
- `option.internal` = 内部标识（来自 data）
- 填写按 `letter` 匹配，`key` 用 `internal` 保稳定

修复前后对比（同一道题的真实渲染）：

| 修复前 | 修复后 |
|---|---|
| `D 核心是加强党的领导…` | `A 核心是加强党的领导…` |
| `A 核心是正风肃纪反腐…` | `B 核心是正风肃纪反腐…` |
| `C 核心是党的自我革命…` | `C 核心是党的自我革命…` |
| `B 核心是党的政治建设…` | `D 核心是党的政治建设…` |

## 五、安全与资源（按要求）

| 要求 | 实现 |
|---|---|
| 请求鉴权 | 每次启动随机 token，`X-Vision-Token` |
| 图片尺寸限制 | base64 ≤ 12 MiB、解码 ≤ 8 MiB、边长 ≤ 4096（PNG/JPEG 头解析） |
| 超时 | 服务端会话 120s，客户端 130s |
| 并发限制 | 单并发 + 队列上限 4，超出 429 |
| 错误处理 | 400/401/403/413/415/422/429/500/503 分别返回明确错误码 |
| 临时文件 | 请求结束立即删除图片；headless 的 task/out/err 文件也在会话结束后删除 |
| 日志脱敏 | 只记录题目 ID、耗时、状态；不记录图片内容与 Key；stderr 中 `sk-*` 会被替换 |
| 凭据解耦 | 优先级：`VISION_API_KEY`/`DEEPSEEK_API_KEY` 环境变量 → `--key-file` → 显式 `--allow-dev-credentials` 才读个人 DSH 凭据（**发行版不要用**） |
