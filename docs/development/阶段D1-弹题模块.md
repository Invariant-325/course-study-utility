## 三、关键设计

### 3.1 为什么必须有本地代理

| 风险 | 处理 |
|---|---|
| Key 写进脚本源 | 会被分发，禁止 |
| Key 存 localStorage | 页面脚本可读，**Config.set 直接拒绝** |
| 页面 fetch 调 127.0.0.1 | 触发 PNA 预检 + CORS + 混合内容，基本不可行 |

所以：Key 只在代理进程内存；脚本只持随机 token；网络出口只有一个函数 `gmRequest()`，无 `GM_xmlhttpRequest` 时**直接失败**，绝不回退到页面 fetch。

### 3.2 成本控制（防无限烧 token）

| 机制 | 位置 |
|---|---|
| 题目 hash 去重 | `QuizModel.parse` 生成，`Llm.cache` 命中即返回 |
| 同题不重复请求 | `QuizRunner` 的 `lastHash` |
| 并发锁 | `Llm.busy`，同一时刻只一个请求 |
| 校验失败不重试 | 越界答案重试同样内容也没用 |
| 网络错误有限重试 | 默认 2 次，指数退避 |
| 失败结果也缓存 | 避免同题反复失败 |
| 默认关闭 | `llmEnabled: false`，未开启时检测到题目只提示，不发请求 |

### 3.3 严格 JSON 与选项对齐

`extractJson()` 只做 `JSON.parse`，**不 eval、不 new Function**；随后 `validateAnswer()` 校验：

- 只接受 `A-H` 单字母；`Z` 或 `AB` 这类**显式报错**（不能静默丢弃后当作合法）
- 越界字母必须存在于真实选项集合
- 单选题/判断题只能 1 个答案
- 空答案拒绝
- `confidence` 夹到 0..1

校验失败 → 转人工，不自动勾选。

### 3.4 提交边界

- 脚本只负责「应用建议（勾选）」
- 「提交」必须用户点击，且**二次确认**（`window.confirm`）
- 找不到提交按钮时不强行点击，提示「该题型可能勾选即生效」

### 5.3 由此发现并修复的 bug

**该修复之后未再重新注入复验**（重新注入需再粘贴 143KB 并重跑一遍流程）。
